## 题目背景

> 微光工作室学习小组准备制作一个学习资源导航页，用于向新同学推荐 HTML、CSS、JavaScript 和前端工具等学习资料。页面已经准备好了，但学习资源暂时都直接写在网页代码中。每次修改内容，都需要重新修改页面。
>
> 于是，大家决定搭建一个简单的数据服务，让页面可以通过 API 获取工作室介绍和学习资源。
>
> 这一次，你不再只是 API 的使用者，而是要尝试成为 API 的创造者。

### 任务一：启动本地服务器

在项目目录打开终端，运行：

```bash
node server.js
```

正常情况下，终端会显示：

```text
服务器已启动：http://localhost:3000
```

在浏览器中访问：

```text
http://localhost:3000
```

如果页面可以打开，说明服务器已经开始工作。

试着思考：

- <Badge text="localhost" /> 表示什么？<Badge text="3000" /> 是什么？为什么运行服务器后，终端没有立即结束？修改服务器代码后，为什么通常需要重新启动？

> 服务器创建、静态页面返回和监听端口的代码已经提供，不必从零写完整个服务器，但你需要阅读这些代码！

### 任务二：完成工作室介绍接口

请打开 <Badge text="server.js" />，找到对应的 <Badge text="TODO" />，完成接口：

```text
GET /api/studio
```

访问：

```text
http://localhost:3000/api/studio
```

服务器应返回 JSON 格式的数据，例如：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {
    "name": "微光工作室",
    "direction": "前端",
    "description": "xxxxxxxxx"
  }
}
```

代码中已经提供了 <Badge text="sendJson()" /> 工具函数，可以先读懂它，再考虑应该向它传入什么内容。

可以了解：

- JavaScript 对象和 JSON 有什么联系？
- <Badge text="JSON.stringify()" /> 有什么作用？
- <Badge text="Content-Type: application/json" /> 表示什么？
- 为什么要设置 <Badge text="charset=utf-8" />？

### 任务三：返回全部学习资源

<Badge text="data/resources.js" /> 中已经准备好了学习资源。

每条资源的数据结构类似：

```js
{
  id: 1,
  title: 'MDN Web Docs',
  category: 'HTML',
  description: '适合查阅前端知识的文档网站',
  url: 'https://developer.mozilla.org/'
}
```

请完成：

```text
GET /api/resources
```

访问后，应返回全部学习资源：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": [
    {
      "id": 1,
      "title": "MDN Web Docs",
      "category": "HTML",
      "description": "适合查阅前端知识的文档网站",
      "url": "https://developer.mozilla.org/"
    }
  ]
}
```

尝试使用服务器**已经读取的** <Badge text="resources" />。

可以思考：

- <Badge text="require()" /> 在这里做了什么？
- 为什么把数据单独放在一个文件中？
- 返回对象与返回数组有什么区别？

### 任务四：随机推荐一条资源

请完成：

```text
GET /api/random-resource
```

每次访问时，从资源数组中随机选择一条并返回。

可能的结果：

```json
{
  "code": 200,
  "message": "今天推荐你看看这条资源",
  "data": {
    "id": 3,
    "title": "现代JavaScript教程",
    "category": "JavaScript",
    "description": "从基础语法逐步了解现代JavaScript",
    "url": "https://zh.javascript.info/"
  }
}
```

这里可能会用到：

```js
Math.random()
Math.floor()
resources.length
```

- <Badge text="Math.random()" /> 返回的范围是什么？
- 怎样生成一个合法的数组下标？
- 为什么数组最大下标是 <Badge text="length - 1" />？

完成后多刷新几次，看看结果是否发生变化。

### 任务五：处理不存在的地址

当用户访问不存在的 API，例如：

```text
http://localhost:3000/api/hello
```

服务器应返回：

```json
{
  "code": 404,
  "message": "你访问的接口不存在"
}
```

同时将 HTTP 状态码设置为 <Badge text="404" />。

可以思考：

- JSON 数据中的 <Badge text="code: 404" /> 与 HTTP 响应状态码有什么区别？
- 常见的 <Badge text="200" />、<Badge text="404" /> 和 <Badge text="500" /> 大致表示什么？
- 为什么服务器不能对不存在的地址一直不作响应？

### 任务六：让页面使用自己的API

请打开：

```text
public/index.js
```

补全其中的 <Badge text="TODO" />，使用 <Badge text="fetch()" /> 请求：

```text
/api/resources
```

并把返回的资源展示到页面中。

页面至少应显示：

- 资源名称；
- 资源分类；
- 简短介绍；
- 可以点击访问的链接。

页面结构、资源卡片函数和样式已经提供。只需要完成“获取数据并逐条添加到页面”的核心过程。

完成后，可以在浏览器开发者工具的 <Badge text="Network" /> 面板中找到该请求，观察：

- 请求地址；请求方式；状态码；响应数据。

### 基础要求汇总

| 请求方式 | 请求地址 | 功能 |
| --- | --- | --- |
| GET | <Badge text="/" /> | 返回前端页面 |
| GET | <Badge text="/api/studio" /> | 返回工作室介绍 |
| GET | <Badge text="/api/resources" /> | 返回全部学习资源 |
| GET | <Badge text="/api/random-resource" /> | 随机返回一条资源 |
| GET | 其他地址 | 返回404信息 |

> 只要求 GET 请求。不需要学习数据库、用户登录、权限管理或完整的增删改查。
>

### 自由探索

下面均为选做，可以根据兴趣选择。

**1. 按分类筛选**

支持：

```text
GET /api/resources?category=JavaScript
```

只返回对应分类的资源。

**2. 根据ID查找资源**

支持：

```text
GET /api/resources/1
```

返回指定资源，不存在时返回 404。

**3. 增加前端搜索**

在页面中加入搜索框，根据名称或介绍筛选资源。

**4. 使用Express重写**

尝试安装 Express，并使用：

```js
app.get('/api/resources', (request, response) => {
  // 返回数据
});
```

重写服务器。思考框架替你简化了哪些内容。

**5. 尝试POST请求**

增加一个简单留言接口，将留言临时保存在数组中即可。
